## 1. A 级决策：影响架构和范围

### D-A01：2D 卡通视觉基准

- **状态：** VALIDATING
- **背景：** 「统一 2D 卡通风格」无视觉锚点则无法验收（PRD 评审 A1）。
- **选项：** ①每只猫独立风格；②统一风格 + 基准图。
- **决定：** 建立 KeyCat 统一 2D 卡通视觉风格；使用 1–3 张正式风格基准图；建立 VISUAL_GUIDELINES.md；Phase 3 开始前冻结正式参考图。
- **理由：** 统一风格降低 AI 生成成本并保证动画一致性；基准图使「风格相符」可验收。
- **影响：** 角色生成提示词、角色外观验收、Sprite 动画资源、角色预览界面。
- **验证：** Phase 0 产出候选基准图；Phase 3 冻结。

### D-A02：多图照片融合

- **状态：** ACCEPTED
- **背景：** 单张照片无法覆盖背部花纹、侧脸等特征（A2）。
- **选项：** ①仅单张；②多张任选其一；③主照片 + 辅助参考融合。
- **决定：** 每只猫支持 1–5 张照片；1 张主照片；最多 4 张辅助照片；辅助照片用于补充不同角度和外观特征；默认要求所有照片属于同一只猫；用户可更换主照片、删除和替换辅助照片。
- **理由：** 利用多角度信息提升特征还原，同时控制首版工作流复杂度。
- **影响：** 照片导入界面、多图参考工作流、特征提取、生成质量和显存预算。
- **验证：** Phase 0-10 多图融合原型。

### D-A03：结构化特征提取

- **状态：** ACCEPTED
- **背景：** 生成前需要可检查、可修正的外观描述（A3）；本地识别模型在 8GB 显存下成本高。
- **选项：** ①IP-Adapter 端到端隐式提取；②结构化标签 + 用户修正；③本地多模态模型自动识别。
- **决定：** 采用结构化外观特征，首版字段：毛色、花纹、眼睛颜色、脸型、耳朵形态、毛发长度；用户可修正关键标签；生成工作流读取结构化特征。**识别主体暂定方案：基线为用户从有限枚举手动选择 + 参照照片修正；自动识别作为后续增强，Phase 3 原型评估。**
- **理由：** 结构化数据让外观调整（CAT-012）无需重构数据模型；手动枚举基线不阻塞、不依赖额外模型资源。
- **影响：** Character Schema、生成提示词、后续外观调整功能。
- **验证：** Phase 3 原型评估自动识别可行性。

### D-A04：动作模板规格

- **状态：** VALIDATING
- **背景：** 动画规格影响 Sprite Sheet 尺寸、AI 一致性难度和渲染性能（A4）。
- **选项：** ①AI 为每只猫生成全套动作；②统一动画模板。
- **决定：** 采用统一动画模板。原型建议值：Idle 8帧/8FPS、Sleep 4帧/2FPS、Look 4帧/4FPS、Walk 8帧/10FPS、Stretch 8帧/6FPS（不循环）；暂定帧尺寸 512×512 px/帧；1.0 必须支持 Idle、Sleep、Look。Phase 3 前通过原型冻结：帧数、帧率、帧尺寸、透明边界、动画原点、左右朝向翻转规则（镜像或独立帧）。
- **理由：** 统一模板显著降低生成成本；帧尺寸与翻转规则是冻结清单中最影响资源体积与渲染的参数。
- **影响：** 生成工作流、Sprite Sheet 规格、渲染性能、资源体积。
- **验证：** Phase 3 动画原型实测后冻结。

### D-A05：多角色管理

- **状态：** ACCEPTED
- **背景：** 用户需要反复生成和比较，不能替换即丢失（A5）。
- **选项：** ①仅单角色替换；②角色库 + 单活动角色。
- **决定：** 1.0 支持多个角色保存；同一时间只显示一个活动角色；默认系统角色保留；新生成角色不自动覆盖现有角色；删除角色不影响其他角色。
- **理由：** 区分「角色库 / 活动角色 / 默认角色」避免多猫同时运行扩大首版范围，又保留比较自由。
- **影响：** 角色存储结构、桌面猫加载器、主界面角色管理。
- **验证：** Phase 3/4 验收。

### D-A06：双拼范围

- **状态：** ACCEPTED / DEFERRED
- **背景：** 雾凇自带多套双拼方案，需明确 1.0 验收边界（A6）。
- **选项：** ①1.0 纳入双拼验收；②仅全拼 + 声母简拼。
- **决定：** 1.0 支持全拼和声母简拼；1.0 不纳入双拼验收；双拼方案文件随上游保留；后续版本评估雾凇提供的双拼方案。
- **理由：** 控制首版验收范围；配置文件保留不增加验收负担。
- **影响：** IME-014 输入方案配置、验收用例、测试范围。
- **验证：** 无（范围决策）。

### D-A07：智能联想定义

- **状态：** DEFAULT
- **背景：** 「智能联想」无定义则不可验收（A7）。
- **选项：** ①自研预测引擎；②AI 整句补全；③复用雾凇 Lua 联想。
- **决定：** 1.0 不要求 AI 整句补全；基础词语联想作为 P1 可选能力；优先复用雾凇现有 Lua 机制；不自研预测引擎；具体触发规则和验收语料另行定义。
- **理由：** 先验证现有能力，避免无验收标准的范围膨胀。
- **影响：** IME-012、Phase 1 范围。
- **验证：** Phase 0 验证雾凇 Lua 联想行为后写入详细规格。

### D-A08：统一更新机制（IME-017）

- **状态：** ACCEPTED
- **背景：** 上游 Weasel 自带更新检查会把用户引回原版；fork 必须接管更新（A8）。
- **选项：** ①保留上游更新入口；②禁用并由 KeyCat 统一管理。
- **决定：** 关闭或禁用上游面向用户的独立更新入口；KeyCat 统一管理组件更新；更新检查数据源为 KeyCat 仓库自身的 GitHub Releases，版本清单记录「KeyCat 版本 ↔ Weasel/librime/Rime Ice 上游 commit」映射；更新前备份；更新包完整性校验；更新失败回滚；不覆盖用户词库；持续跟踪上游安全修复。
- **理由：** 品牌 fork 的更新链必须自有可控；无自有服务器条件下 GitHub Releases 是可行数据源。
- **影响：** UPDATE_POLICY.md、安装器、P1-07/P1-11。
- **验证：** Phase 0-07 验证关闭入口可行性；Phase 1 更新演练。

### D-A09：统一安装器与权限

- **状态：** VALIDATING
- **背景：** TSF 注册权限需求存在 per-user / per-machine 两种可能，不能预设（A9）。
- **选项：** ①主程序全程管理员运行；②统一入口 + 输入法独立提权安装阶段。
- **决定：** 用户通过统一 KeyCat 安装入口安装产品；输入法可通过独立安装阶段完成部署；主程序不要求始终管理员权限；尽量减少重复提权；Phase 0 实测 per-user 与 per-machine 安装方式，根据 TSF 注册实际权限需求确定 UAC 策略。
- **理由：** 最小权限原则；实测避免基于错误假设设计安装器。
- **影响：** PRD §6、P0-06、P1-05。
- **验证：** Phase 0-06 双方案实测。

### D-A10：词库同步定义

- **状态：** ACCEPTED
- **背景：** 「同步」一词有云同步与本地备份两种解读（A10）。
- **选项：** ①云同步；②本地备份/恢复。
- **决定：** IME 词库同步指本地备份和恢复；1.0 不做云同步；用户可以导出和导入词库及自定义短语。
- **理由：** 个人使用定位下不引入账户系统和云端存储。
- **影响：** P1-08、隐私边界。
- **验证：** Phase 1 备份/恢复验收。

## 2. B 级默认假设

### D-B01：候选生成数量 — DEFAULT
决定：每次生成默认 4 张候选图，支持重新生成。
理由：给用户选择空间同时控制生成耗时。
验证：Phase 3 体验验证。

### D-B02：角色生成性能 — DEFAULT
决定：8GB 显存下单张图目标不超过 60 秒；必须固定测试环境后测量，不对所有显卡和模型组合做绝对保证。
理由：有依据的目标线而非伪保证。
验证：Phase 0-10 实测记录。

### D-B03：无效照片处理 — DEFAULT
决定：非猫、多猫、低质量照片或主体识别置信度不足时提示用户，不得静默生成；阈值通过样本测试确定，不预设未经验证的数值。
理由：防止垃圾输入静默浪费生成资源并误导用户。
验证：Phase 3 用样本集确定阈值。

### D-B04：AI 失败降级 — DEFAULT
决定：失败时保留当前角色、显示错误信息、提供重试、不覆盖旧角色。
理由：生成是创作行为，失败不得破坏已有资产。
验证：Phase 3 故障注入测试。

### D-B05：输入法健康检查 — DEFAULT
决定：联合验证 TSF 注册信息、必要进程和组件状态、真实文本输入成功三项；进程存在不等于可用。
理由：单一信号误报率高。
验证：Phase 1 健康查询实现 + P0-09 基线环境验证。

### D-B06：多用户数据策略 — VALIDATING
决定：程序组件采用产品选定的系统级部署方式；用户配置和词库按 Windows 用户隔离；Rime 用户数据采用对应用户的数据目录。Phase 0 必须验证 Windows 安装范围、权限和 Rime 实际数据路径，不得仅凭预设路径实现。
理由：Rime 实际数据目录随部署方式变化，实测优先。
验证：Phase 0-06。

### D-B07：输入法修复 — DEFAULT
决定：修复包括重新注册必要 TSF 组件、检查和修复程序文件、重建必要默认配置；必须保留用户词库和个人配置。
理由：修复的本义是恢复运行而非清除个人数据。
验证：Phase 1-06 修复演练。

### D-B08：词库更新 — DEFAULT
决定：手动检查、下载和导入；不做云端自动同步。
理由：与个人使用定位和离线原则一致。
验证：Phase 2 更新入口验收。

### D-B09：中英文切换 — DEFAULT
决定：沿用雾凇默认配置和快捷键行为，不自行重新发明输入规则。
理由：上游默认已经过大量用户验证。
验证：Phase 1-04 功能测试。

### D-B10：AI 磁盘空间 — VALIDATING
决定：10GB 作为初步磁盘预算；实际空间需求由模型、缓存和工作流测量确定；安装或启用前进行空间检查和提示。
理由：预算仅为起点，下载缓存与临时推理文件会扩大需求。
验证：Phase 0-10 实测占用。

## 3. C 级：性能和质量基线

### D-C01：输入法原版性能基线 — ACCEPTED
决定：Phase 0 / Phase 1a 必须建立原版 Weasel + Rime Ice 基线。
理由：无基线则回归预算无意义。

### D-C02：测试语料 — ACCEPTED
决定：目标语料为 500 条输入句子；语料来源需确认许可和再分发条件；不允许再分发的语料仅本地使用、不入库。
理由：许可证风险前置。

### D-C03：测量指标 — ACCEPTED
决定：测量首候选响应延迟、候选窗口弹出耗时、内存占用、首选候选命中率、长时间运行稳定性。

### D-C04：回归预算 — ACCEPTED
决定：延迟类指标相对原版回归不超过 10%；首选命中率不应因 KeyCat 集成而下降；内存变化必须记录和解释；所有比较固定环境、配置、语料和初始用户词频。
理由：可比较性依赖受控变量。

## 4. 产品技术决策

### D-T01：Weasel 原生前端 — ACCEPTED
决定：不重写 Weasel Windows TSF 前端。
理由：TSF 系统级复杂度高，复用成熟前端风险最小。

### D-T02：候选窗口 — ACCEPTED
决定：保留 Weasel 原生候选窗口，采用 KeyCat 主题。
理由：轻量品牌化（改名、图标、配色），保持上游交互逻辑。

### D-T03：输入法品牌 — ACCEPTED
决定：面向用户统一使用 KeyCat 输入法名称，必要的上游版权信息继续保留。
理由：品牌统一与 GPL 合规并存。

### D-T04：角色生成本地优先 — ACCEPTED
决定：默认本地生成，不要求云端 AI 服务。
理由：隐私原则 + 用户无持续 API 成本。

### D-T05：AI 与输入法进程隔离 — ACCEPTED
决定：AI Worker 不得成为输入法的运行依赖。
理由：产品核心原则「AI 不阻塞输入法」的进程级保证。

### D-T06：默认角色回退 — ACCEPTED
决定：AI 生成失败或角色资源损坏时回退到默认猫咪。
理由：桌面猫必须永远可用。

### D-T07：产品定位与上游条款 — ACCEPTED
决定：KeyCat 1.0 定位为个人使用和内部交流，不做公众分发；KeyCat 上游（ElloboDK/KeyCat）代码按其 README 条款使用（仅供个人使用和内部交流，不用于商业分发）；该约束列入 THIRD_PARTY_LICENSES.md 必含条目。
理由：尊重上游授权边界，规避许可风险。
影响：Phase 5 发布形态、THIRD_PARTY_LICENSES.md、对外宣传口径。

### D-T08：AI 组件分发 — ACCEPTED
决定：AI 模型与组件按需下载（不进安装包）；下载必须校验哈希（SHA-256）与来源；下载源可配置（支持国内镜像）。
理由：安装包保持小巧；模型体积数 GB 且更新频繁。
影响：Character Studio 模型管理器、P0-10。

## 5. 路线图决策

### D-R01：macOS 适配移出路线图 — DEFERRED
- **背景：** PRD 早期草案含 macOS 阶段；负责人业余时间开发，需要降低长期维护负担。
- **选项：** ①保留 Phase 6 未排期；②移除路线图。
- **决定：** macOS 适配移出路线图；PRD 删除 Phase 6 与「后续平台」条目；仓库保留 `mac/` 源码快照，不承诺维护；如未来恢复，将评估鼠须管（Squirrel）而非复用 Weasel。
- **理由：** Windows 优先交付价值；macOS 维护心智成本与收益不匹配。
- **影响：** PRD §1/§9/§11、ARCHITECTURE.md、CI 规划（无 macOS CI）。
- **验证：** 无（路线图决策）。如恢复需新决策取代本条。

## 6. 决策变更规则

已确认决策不能由开发人员或 AI 编码代理自行修改。

修改必须：
1. 提交变更原因。
2. 说明影响模块。
3. 说明对工期、架构和测试的影响。
4. 更新 PRD。
5. 更新 DECISIONS.md。
6. 经过项目负责人确认。

VALIDATING 项在完成技术验证后更新为 ACCEPTED 或调整为其他明确状态。

DEFERRED 项不得未经确认进入 1.0 开发范围。

已废弃决策不删除，标记 SUPERSEDED 并链接替代决策。
