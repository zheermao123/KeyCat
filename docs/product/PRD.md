## 1. 产品定义

### 1.1 产品定位

KeyCat 是一款整合中文输入法、个性化桌面猫咪和本地 AI 角色生成能力的 Windows 桌面软件。

核心组成：

1. KeyCat Input：基于 Weasel + Rime + Rime Ice 的中文输入法。
2. KeyCat Desktop：桌面宠物、托盘、设置和统一管理程序。
3. KeyCat Character Studio：根据用户猫咪照片生成 2D 卡通角色。

### 1.2 产品核心原则

- 输入法是产品的生产力核心。
- 桌面猫是产品的个性化体验核心。
- AI 是个性化角色创作工具。
- 输入法与桌面猫独立运行。
- AI 推理不得阻塞输入法。
- 基本输入功能支持离线使用。
- 默认本地处理用户照片、角色和输入法个人数据。
- 不重复开发已有成熟的输入法引擎和 Windows 输入法前端。
- KeyCat 负责统一品牌、安装、配置、更新和用户体验。

### 1.3 首版目标

KeyCat 1.0 必须交付：

- 可在 Windows 系统中独立使用的 KeyCat 中文输入法。
- 基于雾凇拼音的中文输入体验。
- KeyCat 品牌候选窗口主题。
- 输入法安装、卸载、修复和更新管理。
- 原有桌面猫基本功能。
- 用户照片生成 2D 卡通猫咪。
- 多角色本地保存和切换。
- 至少 Idle、Sleep、Look 三种动画。

## 2. 技术架构

### 2.1 输入法技术栈

| 组件 | 技术 | 职责 |
|---|---|---|
| Windows 输入法前端 | Weasel | TSF 接入、候选窗口、系统注册 |
| 输入法核心 | librime | 输入解析、候选词、词频 |
| 中文输入方案 | Rime Ice | 拼音配置、词库和相关脚本 |
| 产品管理 | KeyCat | 安装、配置、备份、更新、品牌 |

不重新开发 Weasel 的 Windows TSF 前端，不自行实现 Rime 引擎。

### 2.2 品牌与候选窗口

- 对用户统一使用 KeyCat 输入法名称。
- 保留 Weasel 原生候选窗口和交互逻辑。
- 使用 KeyCat 主题。
- 保留必要的 Weasel、Rime 版权和许可证信息。
- 通过技术审计确认 Windows 输入法列表中的显示名称、图标和品牌资源可定制范围。

### 2.3 进程边界

- KeyCat Desktop：桌面宠物和产品管理。
- Weasel：Windows 输入法前端。
- Rime：输入法核心。
- Character Studio：角色生成管理。
- AI Worker：本地 AI 推理。

输入法不得依赖 KeyCat 主窗口存活。AI Worker 与输入法必须进程隔离。

### 2.4 数据边界

数据至少分为：

- 程序安装目录。
- KeyCat 用户配置。
- Rime 用户配置。
- 用户词库和词频。
- 用户角色资源。
- AI 模型和缓存。
- 日志与诊断数据。

程序升级不得直接覆盖用户数据目录。

## 3. KeyCat Input 需求

### 3.1 P0 功能

- Windows 系统输入法注册。
- 中文拼音输入。
- 全拼。
- 声母简拼。
- 候选词显示。
- 数字选词。
- 空格选词。
- 中英文切换。
- 常用中文标点。
- 动态词频。
- 用户词库保存。
- 离线输入。
- KeyCat 候选窗口主题。
- 安装、卸载和修复。

### 3.2 输入方案范围

KeyCat 1.0 默认使用 Rime Ice 拼音方案。

支持：
- 全拼。
- 声母简拼。

不纳入 1.0：
- 双拼方案（D-A06）。
- 多套双拼布局。
- 其他输入法方案。

双拼作为后续版本的扩展能力，不得在 Phase 1 中无依据扩大实现范围。

中英文切换和上屏行为沿用雾凇默认配置，除非测试发现明确的兼容性或体验问题（D-B09）。

### 3.3 候选窗口

采用 Weasel 原生候选窗口。

KeyCat 主题至少定义：
- 默认状态。
- 当前选中候选。
- 候选序号。
- 候选文本。
- 输入编码。
- 中英文状态提示。

必须验证：
- 常见屏幕缩放比例。
- 高 DPI。
- 多显示器。
- 长候选文本。
- 候选窗口位置和方向。

### 3.4 词频与用户数据

- 动态词频本地保存。
- 用户自定义短语本地保存。
- 用户词库支持本地备份和恢复（D-A10）。
- 不做云端词库同步。
- 升级不得覆盖用户词库。
- 修复不得删除用户词频和自定义配置。

### 3.5 智能联想

1.0 不要求 AI 整句补全（D-A07）。

P1 可选范围：
- 基于雾凇已有 Lua 机制实现基础词语联想。
- 使用已有方案和脚本，不自研预测引擎。
- 具体联想触发方式、候选规则和开关由 Phase 0 验证后写入详细规格。

未定义并未通过验收的联想功能不得作为 1.0 发布阻塞项。

### 3.6 输入法统一更新（IME-017）

KeyCat 统一更新管理（D-A08）：

- 禁用或关闭上游面向用户的独立更新入口。
- KeyCat 统一管理 Weasel、librime、Rime Ice 的版本清单。
- KeyCat 负责检查、下载、校验和更新；更新检查数据源为 KeyCat 仓库自身的 GitHub Releases，版本清单记录「KeyCat 版本 ↔ 上游 commit」映射。
- 更新前备份用户数据。
- 更新失败可回滚。
- 跟踪上游安全修复。
- 不得将 KeyCat 产品版本与所有第三方组件版本强行绑定。

### 3.7 安装、卸载与修复

安装：
- 检查 Windows 环境。
- 检查组件状态。
- 安装输入法组件。
- 安装默认配置。
- 初始化用户数据。
- 注册输入法。
- 引导用户启用 KeyCat 输入法。

卸载：
- 清理 KeyCat 输入法组件。
- 清理对应注册信息。
- 不影响其他输入法。
- 明确区分程序卸载和用户数据删除。

修复（D-B07）：
- 检查组件完整性。
- 重新注册必要的 TSF 组件。
- 重建必要的默认配置。
- 保留用户词库、词频和自定义短语。

### 3.8 输入法健康状态

不能只依据进程存在判断输入法是否正常（D-B05）。

健康状态至少需要联合验证：

1. Windows 输入法注册信息有效。
2. Weasel 必要组件和进程正常。
3. 实际文本编辑环境中能够完成测试输入。

其中第三项应由测试环境完成，不能在普通运行状态下未经用户许可向前台应用自动输入测试文字。

## 4. KeyCat Character Studio 需求

### 4.1 产品目标

用户导入真实猫咪照片，生成具有对应外观特征的 2D 卡通角色。

首版不做 3D 角色生成。

### 4.2 照片导入与多图策略（D-A02）

KeyCat 1.0 支持：

- 最少 1 张照片。
- 最多 5 张照片。
- 1 张主照片。
- 最多 4 张辅助照片。

照片用途：

- 主照片决定整体主体和主要视觉参考。
- 辅助照片补充不同角度、毛色、花纹、眼睛、耳朵等特征。
- 所有照片默认应属于同一只猫。
- 用户可以更换主照片、删除和替换辅助照片。

多图融合应尽可能提取一致的身份特征，不能简单将多张图片的特征无约束叠加。

照片质量不足、疑似多只猫或无法识别主体时，应明确提示用户重新选择（D-B03）。

### 4.3 视觉风格基准（D-A01）

建立 KeyCat 统一 2D 卡通风格。

风格基准需要通过 1–3 张正式参考图确定，并纳入 `docs/character-studio/VISUAL_GUIDELINES.md`。

至少定义：
- 线条风格。
- 色彩风格。
- 头身比例。
- 五官表现。
- 阴影与高光。
- 透明背景要求。
- 角色在桌面中的视觉比例。

正式参考图在 Phase 3 开始前冻结。

生成角色必须同时满足：
- 与用户猫咪主要外观特征相符。
- 与 KeyCat 统一视觉风格一致。
- 适合桌面显示和动画模板使用。

### 4.4 结构化特征提取（D-A03）

生成流程采用结构化外观特征。

首版字段：
- 毛色。
- 花纹。
- 眼睛颜色。
- 脸型。
- 耳朵形态。
- 毛发长度。

识别主体暂定方案：基线为「用户从有限枚举中手动选择 + 参照照片修正」，自动识别作为后续增强，Phase 3 原型时评估（见 DECISIONS D-A03）。

用户可以在生成前修正关键特征。

特征结构应由 `character-schema` 管理，不能直接将模型提示词当作唯一数据结构。

### 4.5 角色生成流程

1. 导入照片。
2. 检查照片数量、质量和主体。
3. 确定主照片及辅助照片。
4. 提取结构化特征。
5. 用户检查和调整特征。
6. 本地 AI 生成卡通形象。
7. 生成透明背景资源。
8. 展示候选图。
9. 用户选择或重新生成。
10. 保存角色。
11. 设置活动角色。

### 4.6 候选生成（D-B01 / D-B04）

默认每次生成 4 张候选图。

用户可以：
- 选择其中一张。
- 重新生成。
- 放弃本次生成。
- 保留已有角色不变。

生成失败时：
- 保留当前活动角色。
- 显示明确错误信息。
- 提供重试入口。
- 不覆盖已有角色资源。

### 4.7 性能和硬件（D-B02 / D-T08 / D-B10）

目标硬件考虑 NVIDIA 独立显卡，显存 8GB 或以下。

建议技术栈：
- ComfyUI。
- Stable Diffusion 1.5。
- IP-Adapter。
- rembg。
- Pillow / OpenCV。

8GB 显存下单张图目标生成时间不超过 60 秒，作为目标性能线，必须在固定模型、分辨率、硬件和工作流条件下实测。

支持低显存模式、分批生成、模型按需加载。

AI 模型和组件采用按需下载分发（不进安装包），下载必须校验哈希与来源（D-T08）。

AI 组件安装或启用前检查可用磁盘空间。10GB 作为初步预估预算，实际值根据模型和缓存实测调整。

### 4.8 角色管理（D-A05）

KeyCat 1.0 支持多个角色保存。

规则：
- 角色库可保存多个角色。
- 同一时间只有一个活动角色。
- 可以切换活动角色。
- 可以删除角色。
- 系统默认猫咪始终保留。
- 新角色生成不能自动覆盖当前角色。

### 4.9 动画（D-A04）

1.0 至少支持：
- Idle：待机。
- Sleep：睡觉。
- Look：观察。

以下为原型阶段建议值，最终在 Phase 3 前冻结：

| 动作 | 帧数 | 帧率 | 循环 |
|---|---:|---:|---|
| Idle | 8 | 8 FPS | 是 |
| Sleep | 4 | 2 FPS | 是 |
| Look | 4 | 4 FPS | 是 |
| Walk | 8 | 10 FPS | 是 |
| Stretch | 8 | 6 FPS | 否 |

暂定帧尺寸：512×512 px/帧。Phase 3 冻结清单：帧数、帧率、帧尺寸、透明边界、动画原点、**左右朝向翻转规则**（镜像或独立帧）。

1.0 可以只交付前三种动作。

统一采用 Sprite Sheet 或连续 PNG 帧。资源规格必须包括帧尺寸、排列、透明边界、动画原点和资源版本。

## 5. KeyCat Desktop

- 保留现有桌面猫基础功能。
- 保留托盘菜单和设置。
- 支持角色资源加载。
- 支持活动角色切换。
- 桌面猫可独立退出。
- 关闭主窗口不影响输入法。
- 角色资源异常时回退默认猫咪（D-T06）。

## 6. 安装器与权限（D-A09）

采用统一安装入口。

初步方案：
- KeyCat Desktop 按用户级或产品选定安装范围部署。
- KeyCat Input 通过独立安装阶段部署。
- 需要系统级权限的操作单独提权。
- 不要求 KeyCat 主程序始终以管理员权限运行。
- 不默认假定 TSF 注册的所有操作都需要管理员权限。

Phase 0 必须验证 per-user 和 per-machine 两种部署方式及其权限要求。

安装流程应尽量减少重复 UAC 提示，并在用户取消授权时提供明确处理结果。

## 7. 隐私与安全

- 默认本地处理猫咪照片。
- 默认不上传照片。
- 不记录用户完整输入文本。
- 不将用户输入内容发送至 KeyCat 服务器。
- 不将个人词库写入普通日志。
- 用户照片、角色、词库均存储于本地用户数据目录。
- 私钥和签名凭据不得提交 Git。
- 安装包必须验证文件完整性和来源。
- AI 模型和组件下载必须校验哈希（SHA-256）与来源。
- 遵守 KeyCat 上游项目使用条款：仅限个人使用和内部交流，不用于商业分发（D-T07）。
- 第三方许可证和版权声明必须随发布包提供（THIRD_PARTY_LICENSES.md 须含 KeyCat 上游条款条目）。

### 10.1 输入法功能测试

- 全拼。
- 声母简拼。
- 候选词。
- 数字选词。
- 空格选词。
- 中英文切换。

- 动态词频。

### 10.2 输入法性能基线（D-C01–C04）

Phase 0 / Phase 1a 使用原版 Weasel + Rime Ice 建立基线。

测试语料目标 500 条。

测量：
- 首候选响应延迟。
- 候选窗口弹出耗时。
- 内存占用。
- 首选候选命中率。
- 长时间运行稳定性。

KeyCat 相比原版基线：
- 延迟类指标回归预算不超过 10%。
- 首选命中率不得因 KeyCat 集成和主题修改而下降。
- 内存变化必须记录并解释。

测试时固定环境、输入方案、初始用户词频和语料版本。社区语料须先确认使用和再分发许可。

## 11. 开发阶段与就绪门禁（DoR）

| 阶段 | 目标 | 状态 |
|---|---|---|
| Phase 0 | 现有项目审计、第三方审计、架构和原型验证 | Ready |
| Phase 1 | KeyCat Input MVP | 有条件 Ready |
| Phase 2 | 输入法管理和设置完善 | 待 Phase 1 |
| Phase 3 | 2D 个性化角色生成 | Not Ready |
| Phase 4 | 角色系统与桌面猫整合 | Not Ready |
| Phase 5 | 产品化、安装器、更新和正式发布 | Not Ready |

开发优先级：输入法优先，角色生成并行准备。

**阶段门禁（未满足不得进入对应阶段正式开发）：**
